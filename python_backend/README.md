# Telegram Live Geo Inspector (Автономный локальный сервер)

Локальное приложение для личного использования: мониторинг бессрочной live-геопозиции из личных диалогов Telegram, сохранение истории в SQLite и эвристический поиск аномалий в координатах.

---

## ⚠️ ГЛАВНОЕ ОГРАНИЧЕНИЕ (ПРИНЦИП РАБОТЫ)

Telegram передаёт **только заявленные отправителем данные**:
- широту (`lat`) и долготу (`lon`),
- опциональную погрешность (`horizontal_accuracy` 0–1500 м),
- направление компаса (`heading` 0–360°),
- период трансляции (`live_period`),
- время отправки и правки сообщения (`edit_date` с точностью до 1 секунды).

В протоколе MTProto **ОТСУТСТВУЮТ**:
- признак программной симуляции GPS (Mock Locations / Fake GPS),
- аппаратные данные датчиков GNSS/ГЛОНАСС/GPS (NMEA, SNR, созвездия спутников),
- данные Apple Locator (Find My) или Google Find My Device,
- сетевой IP-адрес или признаки VPN собеседника,
- аттестация устройства (Apple App Attest, Google Play Integrity).

> **Следствие:** Приложение **НЕ МОЖЕТ ДОКАЗАТЬ ПОДМЕНУ** и **НЕ МОЖЕТ ДОКАЗАТЬ ПОДЛИННОСТЬ**.
> Допустимые итоговые формулировки:
> - **«аномалий не найдено»**
> - **«есть подозрительные признаки: <причины>»**
> - **«найдены аномалии: <причины>»**
>
> Строго запрещено выводить: *«GPS подтверждён»*, *«подмены нет»*, *«подмена доказана»*, *«взлом»*, *«подлинность подтверждена»*.
> Любая аномалия расценивается как предупреждение с объяснением, а не как обвинение.

## 🚀 Один запуск, одна команда

Приложение работает в **одном процессе** на FastAPI:
- Порт `3000` и Node.js/Next.js рантайм больше **не требуются** для локальной работы.
- FastAPI напрямую отдаёт статический фронтенд (HTML5 + vanilla JS + Leaflet CDN) на `127.0.0.1:8000`.
- Запуск осуществляется скриптом `./run.sh`.

```bash
chmod +x ./run.sh
./run.sh
```

Скрипт выполняет:
1. Проверку Python 3.11+.
2. Создание папки `data/` с правами доступа `0700` (файлы `0600`).
3. Развёртывание виртуального окружения `venv/` и установку зависимостей из `python_backend/requirements.txt`.
4. Автоматический прогон полного набора тестов (`python3 -m unittest discover -s python_backend/tests`).
5. Генерацию одноразового токена доступа (`secrets.token_urlsafe(32)`) и вывод в консоль готовой ссылки:
   ```
   http://127.0.0.1:8000/#token=<ваш_секретный_токен>
   ```

## 🔒 Безопасность и защита от атак

1. **Только 127.0.0.1**: Сервер привязан строго к `127.0.0.1:8000`.
2. **Токен авторизации**: Фронтенд извлекает токен из `#token=...`, немедленно стирает его из адресной строки (`history.replaceState`), сохраняет в сессии браузера и передаёт в `Authorization: Bearer <token>` и параметре сокета `/ws?token=...`. Без токена возвращается **401 Unauthorized**.
3. **Защита от DNS-rebinding**: Middleware строго валидирует заголовок `Host` (разрешены только `127.0.0.1:8000` и `localhost:8000`). Несанкционированный Host отклоняется с кодом **400 Bad Request**.
4. **Строгий Origin**: Разрешены только локальные Origin (`127.0.0.1:8000` и `localhost:8000`). Посторонний сайт, пытающийся выполнить межсайтовый запрос, получает **403 Forbidden**.
5. **Изоляция данных**: Папка `data/` создаётся с правами `0700`, а SQLite-база и сессия Telethon — с правами `0600`.
6. **Маскирование в логах**: Телефоны, `api_hash`, код и токены никогда не выводятся в логи.

## 🧪 Проверка и тестирование

### 1. Автоматические тесты (16 тестов)
```bash
python3 -m unittest discover -s python_backend/tests
```
Набор тестов проверяет:
- `test_flight_sustained_clean_no_false_alarm`: Устойчивая скорость >350 км/ч (авиаперелёт) помечается «возможно, перелёт» с 0 штрафных баллов; статус остаётся «аномалий не найдено».
- `test_instant_teleport_leap_always_flagged`: Прыжок на 55 км за 4 секунды всегда определяется как аномалия.
- `test_sapsan_train_clean_no_false_alarm`: Поезд «Сапсан» (~180–210 км/ч) не вызывает ложных срабатываний телепортации.
- `test_highway_drive_smoothness_no_false_alarm`: Движение по трассе М11 с естественным шумом GPS не вызывает ложной искусственной гладкости.
- `test_tunnel_signal_loss_gap_resumption`: 15-минутный перерыв в приёме в туннеле помечается как возобновление после пробела без штрафа за скорость.
- `test_timing_metronome_rule_capped_at_five_points`: Ритмичный интервал правок edit_date получает &le; 5 баллов и сам по себе не повышает статус выше «аномалий не найдено».
- `test_bad_reception_within_accuracy_circle_no_false_alarm`: Скачок внутри радиуса погрешности не штрафуется.
- `test_phrasing_strictly_negative_constraints`: Запрет утвердительных формулировок о подлинности.
- `test_missing_token_returns_401` и `test_invalid_token_returns_401`: Защита REST API.
- `test_forbidden_origin_returns_403`: Защита от чужих Origin.
- `test_invalid_host_dns_rebinding_returns_400`: Защита от DNS-rebinding.
